# Software-Security
Course that implements software security practices and how to write code, implement ciphers, certificates and run dependency check reports for vulnerabilities.
**Briefly summarize your client, Artemis Financial, and its software requirements. Who was the client? What issue did the company want you to address?**
  Artemis Financial was a financial institution the offered financial planning to customers. They wanted to modernize their operations and update software security to the most current and effective software security available. 
  
**What did you do well when you found your client’s software security vulnerabilities? Why is it important to code securely? What value does software security add to a company’s overall well-being?**
  I believe I did well in executing the dependency check reports and identifying the dependencies and their known vulnerabilities. It is important to write secure code because the code is the foundation for operating the application. Without secure code, the integrity of any data being used by that application would not be secure. When dealing with financial information that would include personal information, secure code helps keep the integrity of that sensitive data and providing a trustworthy application. With applications that have been written with secure code and tested for vulnerabilities, the company can gain a piece of mind that known risks have been identified and remedied to offer their clients secure communication in their business operations.  
  
**Which part of the vulnerability assessment was challenging or helpful to you?**
  The challenging part of the vulnerability assessment was knowing which vulnerabilities to suppress and which ones to leave. After going through each dependency and its vulnerabilities, I found that all or very close to all that were listed needed to remain and none or 1 be suppressed based on the identified versions listed in each CVE. The dependency check report was helpful, but I was not confident that I was utilizing it correctly. 
  
**How did you increase layers of security? In the future, what would you use to assess vulnerabilities and decide which mitigation techniques to use?**
  Increasing layers of security was done by using HHTPS for secure connections, implementing encryption for communication channels, and running dependency check reports. I used a priority approach to addressing the known vulnerabilities from the report. Focusing on CRITICAL status vulnerabilities first then moving on to those with HIGH status, then MEDIUM, then LOW.
  
**How did you make certain the code and software application were functional and secure? After refactoring the code, how did you check to see whether you introduced new vulnerabilities?**
  I made sure the code and software applications were functional by running them and looking for errors or failure in builds. Once code was refactored it would be saved and then ran again, finding and fixing issues listed as reason why there were errors until the code ran without error and presented a BUILD SUCCESS. To check for new vulnerabilities, I re-ran the dependency check and assesses the new report for any newly listed dependencies. If one was presented then I know it was a new vulnerability that needed to be assessed like the others.
  
**What resources, tools, or coding practices did you use that might be helpful in future assignments or tasks?**
  There were several resources provided that were helpful in understanding how processes work and how to implement them correctly. The NVD site was a very useful tool in assessing vulnerabilities and searching for the fix. This is a site that was very helpful in the coursework and will be helpful in the future. The Java keytool was a great tool to learn about and how to use. It would be helpful in the future when understanding how systems are communicating.
